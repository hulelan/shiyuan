# 补齐诗词正典 —— 交接说明

写给接手这件事的人。已经查清的、已经备好的、以及几处会绊人的地方，都在这里。

**第一轮已经做完**（2026-08）：清了 40 篇重复著录，补进 415 篇，
语料 4,300 → 4,675。脚本在 `tools/import_canon.py` 与 `tools/dedupe_corpus.py`。
本文件同时留着做过什么、以及**哪条路走不通**（第三节，热度榜那件事）。

## 零、这件事要解决什么

一句话：**站上没有《长恨歌》，没有《琵琶行》，没有《念奴娇·赤壁怀古》，
苏轼只有一篇，陆游辛弃疾一篇都没有。** 这件事就是把这些补上。

不是排序问题，不是推荐问题，不是标注问题 —— 是**这些作品压根不在库里**。
当初导入取的是上游文件开头的若干条，取到哪儿算哪儿，于是唐诗那两千篇有
三分之二是宫廷祭祀乐章，太宗皇帝 101 篇而白居易 18 篇。

做完之后，其它一切才谈得上：相似度再准，也推不出库里没有的诗；
检索排序再好，搜《琵琶行》也还是零条。

## 三、更正：上游的热度榜不能用来挑正典

本文件早先版本把 `rank/` 目录当成"挑篇目的依据"，写着"按搜索热度取前 N，
不必凭印象"。**试过了，不行。** 这一节记下为什么，免得下一个人再走一遍。

榜是真的：`rank/poet/poet.tang.rank.N.json` 与 `全唐诗/poet.tang.N.json`
**按下标一一对应**（四部各抽一份全量核对，1000/1000 对齐），
所以连 join 都不必做，`P[i]` 就配 `K[i]`。每条给五个引擎的命中数：

```json
{"author":"李白","title":"橫吹曲辭 洛陽陌","baidu":28,"google":1240000,"bing":16700,"so360":535,"bing_en":21000}
```

问题在于这些数字量的是**标题这个字符串在网上有多常见**，不是这首诗有多有名。
拿白居易试（2983 首，已滤掉残句）：

| 按什么排 | 排在最前的 | 《长恨歌》排第几 |
|---|---|---|
| 五个引擎命中数相加 | 《句 一》《句 二》《句 三》 | — |
| 各引擎内取中位名次 | 《不出》《老去》《人定》《禁中》《城上》 | 1175 / 2983 |
| 各引擎内取最好名次 | 《有感三首 三》《分司》 | 64 |
| 中位名次 + 题目至少四字 | 《重阳日》《有感三首》 | **被规则排除**（题名只有三字）|

《不出》《老去》《人定》都是常用词，随便一搜几百万条。而限定题目字数这条，
头两个被排除的恰是《长恨歌》和《琵琶引》本身。怎么调都救不回来。

**改用选本。** 上游自带两部现成的：

```
全唐诗/唐诗三百首.json     366 首
宋词/宋词三百首.json       280 首
```

几百年公认的选目，《长恨歌》《琵琶引》《声声慢》《永遇乐·千古江山》都在里面。
选本之外仍要补的，列在 `data/curated/canon_must.json` —— 那是人定的名单。
挑正典这件事没有捷径。

两处要留意：

- **宋诗没有对应的选本**，苏轼、陆游、王安石那批只能靠名单。
- **同题多首要指定首句**。陆游名下有八首都叫《示儿》，只写题名取到的是
  《示儿子》，不是"死去元知万事空"那一首。名单里写成
  `["示儿", "死去元知万事空"]` 即可。苏轼的两首《江城子》、
  李清照的两首《如梦令》同理。
- **《念奴娇·赤壁怀古》不在宋词三百首里。** 选本也有选本的取舍，别假定它全。

## 四、动手的顺序

**导入这一步的代码已经写好了**：`tools/import_canon.py`。下面是整条链子。

```bash
# 0) 先清重复著录。语料要扩，这道闸得先装上
./.venv/bin/python tools/dedupe_corpus.py            # 看要删什么
./.venv/bin/python tools/dedupe_corpus.py --write

# 1) 导入正典。第一次会下上游文件（约 150 MB，有缓存）
./.venv/bin/python tools/import_canon.py             # 试运行
./.venv/bin/python tools/import_canon.py --write

# 2) 重建站点产物：卡片、索引、聚合、字词、时间轴全部重算
./.venv/bin/python tools/build_site_data.py

# 3) 重算语义向量（约 6 分钟，需 GPU 与 .venv-ml）
./.venv-ml/bin/python tools/embed_corpus.py --no-cache

# 4) 重算「与此篇相近」与 BM25 检索索引
./.venv/bin/python tools/build_relevance.py

# 5) 新篇目还没有译文/注释/赏析
./.venv/bin/python tools/enrich_glm.py --dry-run     # 看清单与预估
./.venv/bin/python tools/enrich_glm.py
```

第 3、4 步**不能省**。`build_site_data.py` 会保住 `near/` 与 `bm25/` 两个目录，
并在 manifest 里标 `relevanceStale: true`、打印重算命令 ——
也就是说漏跑不会报错，只是相似度和检索排序悄悄用着旧语料算的结果，
新导入的篇目一个邻居都没有。

第 5 步按当前模型的价钱约 \$1.7/1000 首。编辑层同时也是「与此篇相近」的一路信号，
没有译文赏析的篇目邻居明显更松 —— 所以别把它无限期推后。

## 五、几处会绊人的地方

- **`MAX_CHARS = 360` 把长诗滤掉了**（`tools/build_corpus.py:48`）。《长恨歌》
  《琵琶行》《茅屋为秋风所破歌》不在库里就是因为这一条，不是因为没导。
- **`build_site_data.py` 会先清空 `data/site/`** 再重建（KEEP 之外的都删）。跑之前
  确认 `data/enrich/` 是全的 —— 译文都在那里，site 只是产物。
- **时间轴的年份有三种底子**：逐篇断代 / 按作者估算 / 只知朝代。占位年份一律不进
  直方图，否则整个朝代堆在同一格。改 `build_site_data.py` 里那段，记得同步改
  `tools/rebuild_timeline.py`。
- **不要去爬古诗文网 / 古文网的译文、注释、赏析** —— 那是有版权的编辑成果。原文
  是公有领域，chinese-poetry 也是自由许可的，导入正文没有问题。
- 上游 `全唐诗/` 目录里同时装着 `poet.song.*`（全宋诗），别被目录名骗了。

- **李煜不在《全唐诗》里。** 他是南唐后主，上游单独放在
  `五代诗词/nantang/poetrys.json`，四十一首。按唐人去找一定找不到。
  那个文件随文带 `notes`，**不要取** —— 本层只放公有领域原文，注释归编辑层。

- **热度榜文件有对不齐的。** `宋词/ci.song.9000.json` 是 1000 首配 998 条榜，
  而陆游全部 145 首词恰好都在这一份里。早先的写法是"长度不一致就整份跳过"，
  于是陆游一首词也进不来，还不报错。现在的做法是下标对得上就用下标，
  对不上就退回按 (作者,题) 查 —— 不过热度榜本身已经不用来挑篇目了（见第三节）。

- **词牌名有被上游截断的。** 《大酺》在几条记录里只剩一个「大」字，
  照收会得到《大·对宿烟收》这种一看就不对的题。脚本把牌名不足两字的直接舍去。

- **词的标题只有词牌，得自己配首句。** 上游 `rhythmic` 只给曲调名，
  于是库里一度有 28 首都叫《木兰花・玉楼春》，列表上根本分不开。
  现在按「词牌·首句」构题。

- **乐府栏目名混在标题里，会吃掉 cap，也会让 rank 对不上。**
  《全唐诗》的乐府部分把栏目名写进了诗题：本站现有唐诗 2,142 篇，其中
  **1,441 篇（67%）** 带 `杂曲歌辞 ` `相和歌辞 ` `郊庙歌辞 ` 这类前缀。
  同一首诗因此在上游有两条记录、两条 rank：《杂曲歌辞 蜀道难》与《蜀道难》。
  不归一就直接照名单取，李白那 90 篇的额度会有一部分花在自己的副本上。
  `tools/relevance_lib.py` 的 `clean_title()` 就是干这个的（它同时也剥词牌名）。

  注意区分：**同题不同作者是正常的**，不要一并合掉 ——
  《相和歌辞 长门怨》有 17 位作者各写一首，《横吹曲辞 折杨柳》有 13 位。
  `(author, title)` 这个键本身分得开它们，要归一的只是标题里的栏目名。

- **只按 `作者|标题|原文` 去重是不够的。** 那是 `stable_id` 的定义，只挡得住
  一字不差的重复。真正在库里的重复长这样（全库 125 对，涉及 240 篇，
  清单在 `data/dupes.tsv`）：

  | 情形 | 例子 |
  |---|---|
  | 乐府栏目重出 | 《杂曲歌辞 蜀道难》李白 ←→ 《蜀道难》李白 |
  | 精编与导入撞车 | 《江雪》柳宗元（精编）←→ 《江雪》柳宗元（导入）|
  | 归属存疑 | 《行宫》元稹 ←→ 《故行宫》王建 |
  | 传本异文 | 《静夜思》"床前明月光" ←→ "床前看月光" |

  这四类的原文都不是一字不差，`stable_id` 一条也挡不住。
  `relevance_lib.overlap()` 算的是二元组覆盖率，四类都认得出。
  语料要扩到八倍，这道闸得在导入时就装上，否则同一个问题按比例放大。

  顺带一说：这 125 对**现在就该清一轮**，不必等导入。哪一条留、哪一条删
  是编辑判断（《赤壁》该挂杜牧还是李商隐、《静夜思》两个传本要不要都留），
  脚本不替人决定，所以只出清单。

## 六、缓存在哪

`tools/.cache/canon/`（已 gitignore，约 150 MB）：唐诗 58 份、全宋诗 255 份、
宋词 22 份，加两部选本与南唐词。删掉即可重下，`import_canon.py` 会自己补。

`data/.embed_cache/`：语义向量。改邻居算法时不必重嵌，六分钟变二十秒；
改了嵌入文本才要 `--no-cache`。

一处环境上的坑：跑 `embed_corpus.py` 时若网络不通或 Hugging Face 那边慢，
`transformers` 的导入会卡很久（它在启动时要走一遍自己的 models 目录）。
模型已经下过的话，加 `HF_HUB_OFFLINE=1` 会快些。
